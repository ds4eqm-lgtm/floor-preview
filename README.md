# 우리집 바닥 미리보기

새로고침 데코타일 상세페이지용 웹앱
손님이 집 사진을 올리면 AI가 바닥을 찾아서 고른 데코타일이 깔린 모습을 보여줌

접속 주소
https://ds4eqm-lgtm.github.io/floor-preview/

제품별 주소 (그 색상이 먼저 선택된 상태로 열림)
https://ds4eqm-lgtm.github.io/floor-preview/?item=제품코드

파일 구성
index.html  화면과 기능 전체
refine.js  AI가 찾은 바닥 경계를 사진의 벽, 문틀, 걸레받이 선에 맞춰 다듬고 창문 너머 바닥은 빼는 기능
orient.js  바닥 경계선과 원래 바닥 줄눈으로 방의 가로세로 방향과 카메라 기울기를 찾아 바둑판 방향을 맞추는 기능
camera.js  타일 축척 맞추기 (사진 촬영 정보의 렌즈 초점거리, 천장선과 문 윗선으로 카메라 높이 재기)
products.js  제품 목록 (이름, 코드, 이미지, 실제 크기 mm, 시공 방식, 판매 주소)
tiles  제품 이미지 폴더 (타일 한 장, 4장 세트가 없을 때 씀)
planks  우드 판재 묶음 폴더 (모델명.jpg, 판재를 긴 쪽이 가로가 되게 위아래로 쌓은 이미지, 깔린 바닥 사진에서 판재를 한 장씩 오려 만듦)
tiles4  무늬 4장 세트 폴더 (모델명.jpg, 서로 다른 무늬 4장을 2×2로 줄눈 없이 붙인 이미지)
thumbs  색상 고르기 칸에 보이는 작은 이미지
sample  처음 열 때 보이는 예시 방 사진

무늬 4장 세트
타일 한 장 무늬만 계속 깔면 같은 무늬가 반복돼 보여서, 서로 다른 무늬 4장을 칸마다 무작위로 골라 깔고 반 바퀴 돌림도 무작위로 섞음 (8가지 모습)
tiles4 폴더 이미지는 받은 4장 세트(2400×2400, 줄눈 그려진 것)에서 줄눈을 잘라내고 장당 768×768 로 다시 붙인 1536×1536 jpg
새 색상을 넣을 때는 같은 방식으로 tiles4/모델명.jpg 를 만들고 products.js 에 tiles4 줄을 넣으면 됨

제품 분류
products.js 의 category 값으로 색상 고르기 위에 탭이 생김 (지금은 뉴에코홈, 프리미엄600, 프리미엄450, 프리미엄 우드 순서, 순서는 products.js 의 CATEGORY_ORDER)
새 분류를 만들려면 새 제품에 다른 category 이름만 적으면 탭이 자동으로 하나 더 생김

제품 이미지 조건
타일 한 장을 위에서 정면으로 찍고 타일 부분만 잘라낸 jpg
우드는 긴 쪽이 가로, 가로 1000~2000px 정도
시공 사진이나 연출컷은 안 됨

예시 방 바꾸기
sample/room.jpg 를 실제 방 사진으로 바꾸고 sample/room-mask.png 는 지우면 열릴 때 자동으로 바닥을 찾음
sample/room.json 은 예시 방 사진의 원근값(기울기, 화각, 카메라 높이, 타일 방향). 사진을 바꾸면 이 파일도 지우거나 새로 재야 함 (없으면 자동 계산)

빛 처리 (실사처럼 보이게)
벽과 천장처럼 밝은 무채색 면을 흰 벽 기준으로 삼아 사진 노출에 맞춤 (밝은 타일이 흰 벽보다 더 밝게 뜨지 않게)
원래 바닥에 찍힌 밝기 흐름(창가 밝음, 구석 어두움)을 바닥 전체에 입힘
벽 색에서 조명 색을 읽어 타일에 살짝 입힘
사진과 같은 정도의 노이즈를 넣고, 벽과 가구 밑은 살짝 어둡게
밝은 색(흰색, 크림, 아이보리 계열)은 방 밝기에 맞추면 칙칙해 보여서 더 밝혀 줌 (index.html 의 BRIGHT_LIFT, 짙은 색은 그대로, 원래 색보다 밝아지지는 않게)

조명 색온도
조명 색온도 막대로 2500K ~ 7500K 사이를 고르면 방 전체(원래 사진과 새 바닥)에 그 빛 색을 입혀 보여줌
주백색 4000K, 자연광 5500K, 주광색 6500K 버튼과 사진 그대로 버튼 (한 줄 4칸, 전구색 3000K 는 막대로만)
자연광은 맑은 날 낮 햇빛 기준값 5500K (사진 업계 낮빛 기준, 해 낮을 때 약 5000K, 흐린 하늘 약 6500K)
사진 그대로일 때 보이는 K 값은 벽 색으로 짐작한 대략값
폰 카메라가 빛 색을 어느 정도 알아서 보정하는 것처럼 차이의 일부만 반영 (index.html 의 WB_K)

타일 축척 (600 × 600 이 방 크기에 맞게)
1 사진 파일 속 촬영 정보에서 렌즈의 35mm 환산 초점거리를 읽어 화각을 맞춤 (광각 0.5배, 줌 사진도 맞게)
  촬영 정보가 없는 사진(메신저로 받은 사진, 캡처 등)은 보통 폰 기본 렌즈로 봄
2 AI가 찾은 천장과 벽 경계(천장 높이 2.3m), 문 윗선(2.1m)으로 카메라 높이를 거꾸로 계산
  천장도 문 윗선도 안 보이면 보통 들고 찍는 높이 1.4m로 둠
  그래서 천장 모서리나 방문 윗부분이 같이 나온 사진일수록 타일 크기가 정확함

세부 조정은 없앰 (방향은 방향 버튼, 바닥 범위는 바닥 고치기로)

폰 화면 (가로 899px 이하)
스크롤 없이 한 화면: 위 로고 띠, 제목, 사진, 사진 찍기 버튼, 한 줄 안내, 아래 아이콘 줄
아래 아이콘 한 줄: 색상 고르기, 조명 색, 바닥 고치기, 최근 사진, 타일 계산기, 제품 보기(판매 주소 있을 때만)
사진 저장은 사진 찍기, 앨범에서 고르기 옆 버튼
확대 막대 오른쪽 크게 보기 버튼: 사진만 화면 가득 (안드로이드는 주소창도 숨김, 뒤로 가기나 같은 버튼으로 끝냄)
비교, 방향은 사진 오른쪽 위 작은 버튼
사진 위 제품 이름표에는 이름과 크기만 (시공 방식 문구 없음)
색상, 조명, 바닥 고치기, 최근 사진은 아래에서 창이 올라오고 사진은 남은 칸에 맞춰 줄어듦
창은 X, 창 머리 아래로 끌기, 안드로이드 뒤로 가기로 닫힘
앱 화면 자체 확대는 막음 (사진 확대는 그대로)
컴퓨터 화면은 예전 모양 그대로

확대
사진 오른쪽 아래 확대 버튼, 두 손가락 벌리기, 두 번 톡 치기로 최대 6배까지 확대
확대하면 보이는 부분만 화면 해상도로 다시 그려서 바닥 무늬를 자세히 볼 수 있음, 저장 사진은 늘 전체 화면

최근 올린 사진
손님이 올린 사진 20장까지 손님 기기 브라우저 안(IndexedDB)에 자동 저장
폰에서는 결과 사진 저장하기 바로 위, 컴퓨터에서는 사진 아래에 보임
작은 썸네일을 누르면 AI를 다시 안 돌리고 저장해 둔 바닥 범위, 방향, 조정 값으로 바로 다시 보여줌
바닥 고치기로 칠한 범위, 방향, 렌즈와 카메라 높이도 같이 저장됨
썸네일의 × 로 한 장씩, 모두 지우기를 두 번 눌러 전부 지울 수 있음

참고
바닥 인식 모델은 처음 접속 때 한 번 내려받고 그 뒤로는 브라우저에 저장됨
손님 사진은 손님 기기 안에서만 처리되고 서버로 안 올라감 (최근 사진 저장도 손님 기기 안에만)
products.js, refine.js, orient.js, camera.js 를 고치면 index.html 의 v= 값과 VERSION 값을 같이 올려야 손님 폰에 바로 반영됨

타일 계산기
가로, 세로 길이(m)를 넣으면 바로 계산 (폰은 타일 계산기 아이콘, 컴퓨터는 오른쪽 칸)
면적 = 가로 × 세로, 평수 = 면적 ÷ 3.3, 타일 수량 = 평수 올림 (1박스 = 약 1평)
리무벌 스티커 = 타일 수량(박스) × 450 은 2.3, 600 은 1.2, 우드는 4.1, 소수점 버리고 1장 더함 (index.html 의 CALC)
  기존 새로고침 계산기(serogochim.imweb.me/22)와 같은 결과 (5×3, 4×4, 7×2.5 확인)
